# Cedar 与 Delta 的性能比较

现有证据**不能支持“Delta 更快更优”或直接给两种方法排序**。Delta 报告的准确率数值更高、延迟数值更低，但数据集、硬件、batch 和计时范围同时不同；能耗均没有实测结果。[C:L2-L4][D:L2-L4][PROTOCOL:L2-L6]

| --- | --- | --- |
| 数据集 | Harbor-A | Harbor-B |
| 准确率 | 91% | 94% |
| 单条延迟 | 中位数 20 ms/item | 中位数 8 ms/item |
| 算力配置 | 1 个 CPU | 1 个 GPU |

| 能耗 | 未测量，无数值 | 未测量，无数值 |

| 证据 | [C:L2-L4] | [D:L2-L4] |

表中保留的是已报告配置和测量结果。“1 个 CPU／GPU”只描述硬件配置，不能据此量化或比较计算量、算力利用率和单位计算成本；所给表格没有这些指标。[C:L1-L4][D:L1-L4]

比较受两组条件差异限制。首先，Harbor-A 与 Harbor-B 的样本和标签分布不同，跨数据集的 91% 与 94% 不能建立方法排名。[PROTOCOL:L2-L3] 其次，20 ms 与 8 ms 分别来自 CPU、batch 1、包含预处理的测量，以及 GPU、batch 32、仅推理的测量；现有证据无法分离方法、硬件、批量和计时边界各自的影响。[C:L2-L3][D:L2-L3] 因而不能把这些数值解释为 Delta 的速度优势，也不能把缺失的能耗当作零或据硬件类型推算能耗。

建议按以下方案公平复测：

1. 让两种方法分别在相同的 Harbor-A、Harbor-B 测试集和划分上评估，使用相同标签与准确率计算方式，逐数据集报告结果，避免跨数据集排序。
2. 在同一硬件配置、相同 batch、相同预热与计时边界下运行两者。可以分别设置 batch 1 和 batch 32 两组实验，但每组内必须成对一致。统一报告“预处理＋推理”的单条延迟，并在可用时分列两部分；重复测量并报告中位数及波动。相同硬件、batch、预热、边界与分项计时要求来自比较协议。[PROTOCOL:L4-L5]
3. 在相同测量区间、处理相同数量样本时测量相关硬件能耗，报告总能耗及每条记录能耗。协议要求区间一致并包含相关硬件；这里的归一化指标是复测建议，当前没有可填入的实测数值。[PROTOCOL:L6]

只有上述共同条件下获得成对结果，才可判断准确率与速度的取舍；能耗和计算效率仍须各自的测量支持。限制是当前两份实验表缺少共同数据集结果和能耗测量，协议提供比较规则，并未提供复测结果。[C:L4][D:L4][PROTOCOL:L2-L6]
