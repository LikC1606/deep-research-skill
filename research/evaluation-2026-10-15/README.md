原始材料：

- 每案的 `baseline.md`、`candidate.md`：实际生成的报告，未为评审改写。
- `blind.json`：评审实际收到的任务、语料、报告与 hash。
- `judgments.json`：有具体理由的逐项判断和四维分数。
- `*.commands.jsonl`：计量入口记录的真实 CLI 参数、退出码与耗时，根路径替换为 `<repo>`、`<evaluation>`。
- [results.json](results.json)：版本内容 hash、A/B 身份映射、成本、覆盖状态和汇总。

`direct_coverage` 仅统计 checklist 中标为 direct 的比例；正确计算和有界判断可标为 inference，不代表漏答或错误。价格案例两版均为 1/4 direct，其余 3 项包含透明计算；另两案均为 3/4 direct，最后的建议需要推断。不能把这一指标单独当成总体质量。

读取次数由强制 `local_only` 的 CLI 入口计量，并按 case 上限拒绝额外 `read`；网络调用均为 0。保存的耗时仅覆盖 CLI 子进程，不含模型推理或完整墙钟时间；token 与推理成本未知，因此不能据此声称总成本下降。旧版还执行了一次 `--help`，原样计入 CLI 调用数。

可按 [评估使用说明](../../skills/deep-research/references/reporting-and-evaluation.md) 重新运行 `compare/score`：使用各案固定 case、这里的两份报告和对应种子生成新的比较目录，再提交已有 judgments。原始语料在 `skills/deep-research/evals/`。

这次只有三个小型本地任务、每版每案一份报告和一名 agent 审阅者，没有测试真实网页召回或多轮长报告。两个写作 agent 对这些小任务均选择直接 Read，分章、提纲和审计的行为由本轮定向 CLI 测试覆盖；本组报告没有验证它们对长报告质量的收益。
